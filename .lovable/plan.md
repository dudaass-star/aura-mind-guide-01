# Blog interno da Aura — estratégia SEO orientada a leads (v2)

## O que mudou da v1
- **Removida** Logoterapia como pilar. Método não vende — dor vende. Logoterapia volta como ângulo dentro dos posts, nunca como tema.
- Reestruturado por **5 clusters de DOR**, cada um amarrado a um CTA de conversão específico pro `/v2`.
- Adicionada camada de **bottom-funnel "vs terapia"** — keywords de quem já está procurando solução paga, onde a Aura entra como alternativa de R$ 6,90.

olaaura.com.br: 1 keyword indexada, ~0 tráfego, Authority Score baixíssimo. Regra de ouro: **só atacamos KD ≤ 35**. Acima disso, queima esforço.

## Estrutura obrigatória de todo post

1. **H1 com keyword exata** (≤ 60 chars).
2. **Resposta direta nos 2 primeiros parágrafos** (featured snippet bait).
3. **Sumário com âncoras**.
4. **3–6 H2s em formato pergunta** (captura "People Also Ask").
5. **Listas, tabelas e bullets** — Google adora escaneável.
6. **2 links internos**: 1 pro pilar do cluster + 1 contextual pra outro satélite.
7. **CTA contextual no meio + CTA forte no fim** apontando pro `/v2`, com copy do cluster (ex: cluster Noites → *"Quando a insônia bater de novo às 3h, a Aura tá no seu WhatsApp"*).
8. **Bloco FAQ no fim** (3–5 perguntas) + JSON-LD `FAQPage`.
9. **JSON-LD `Article`** (author "Equipe Aura", datePublished, image).
10. **Meta title ≤ 60**, **meta description ≤ 160** com keyword + benefício + gancho de CTA.
11. **Slug**: keyword exata em kebab-case.
12. **Capa 1200x630** (OG-ready) gerada por IA, estilo visual fixo da marca.

## Trava de qualidade (anti-post sem sentido)

Validação automática antes de publicar:
- Title 30–60 chars, meta 120–160, keyword no H1 + primeiro parágrafo + slug
- Mínimo 1500 palavras, 3 H2s, 1 lista, 1 link interno, 1 CTA pro `/v2`
- Score de leitura PT-BR mínimo (rejeita texto travado)
- Detector de similaridade: >70% similar aos últimos 30 → regenera
- **Bottom-funnel sempre vai pra draft**, nunca publica automático
- Se falhar 2x → salva `status='draft'` + email pra você

## Conversão e medição

- GA4: evento `blog_cta_click` com `cluster` + `slug` + posição (inline/final)
- Meta Pixel: `Lead` quando clica do blog pro `/v2`
- CTA por cluster (copy específico, não genérico)
- "Posts relacionados" no rodapé sempre puxam **do mesmo cluster** (mantém leitor no funil)
- Sticky CTA mobile no `/blog/:slug` apontando pro `/v2`

## Arquitetura técnica (resumo)

```text
cron pg_cron (ter+sex 12h UTC)
    │
    ▼
edge: generate-blog-post
  1. Pega próximo slot da fila editorial (tabela editorial_calendar)
  2. Carrega cluster, keyword, briefing, CTA copy
  3. Gemini 2.5 Pro structured output → post completo
  4. Validação → regenera se falhar
  5. Gera capa 1200x630 (Gemini image, estilo fixo)
  6. Upload bucket "blog-covers"
  7. INSERT blog_posts (status=published OU draft se bottom-funnel)
  8. Pinga IndexNow + sitemap
    │
    ▼
Frontend: /blog (filtro por cluster) + /blog/:slug + sitemap.xml dinâmico
```

## Tabelas novas
- `blog_clusters` (id, slug, name, cta_copy, pillar_post_id)
- `blog_posts` (id, slug, cluster_id, title, excerpt, content_md, cover_url, cover_alt, tags[], meta_title, meta_description, faq jsonb, json_ld jsonb, status, published_at, word_count)
- `editorial_calendar` (id, scheduled_for, cluster_id, keyword, briefing, requires_manual_review bool, status) — fila pré-aprovada
- Bucket público `blog-covers`

## Frontend
- `/blog`: hero + filtro por cluster (chips) + grid de cards (capa, título, badge do cluster, tempo de leitura). Card final = CTA forte pro `/v2`.
- `/blog/:slug`: breadcrumbs, TOC sticky no desktop, capa 1200x630, conteúdo MD (`react-markdown` + `remark-gfm`), CTA inline no meio + CTA banner final + FAQ + "Posts relacionados do mesmo cluster". Sticky mobile CTA pro `/v2`.
- Helmet por post: title, description, canonical, og:image, JSON-LD Article + FAQPage + BreadcrumbList.
- Sitemap dinâmico via edge function `blog-sitemap`. Atualizar `robots.txt`.
- Remover script do Soro do `Blog.tsx`.

## Roadmap
