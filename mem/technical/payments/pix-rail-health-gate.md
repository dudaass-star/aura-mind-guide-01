- `asaas-health-check` (cron a cada 15 min) sonda o gateway ativo (`system_config.pix_gateway`, hoje `asaas`) e grava `system_config.pix_rail_status` (`healthy`, `httpStatus`, `detail`, `checkedAt`).
- `CheckoutV2.tsx` lê `pix_rail_status` no load: se `healthy=false`, esconde o `PaymentMethodToggle`, mostra bloco fixo "Cartão de crédito", força `payMethod='card'` em todos os ciclos (inclusive Trim/Sem/Anual, que antes abriam PIX) e bloqueia `handleOpenPix`. Eventos: `pix_rail_down` / `pix_blocked_rail_down` em `checkout-funnel.ts`.
- Estado atual: conta Asaas restrita (401 com body vazio nos endpoints operacionais; `finance/balance` responde). Último pagamento 05/08.
- `inter-probe` confirma `Deno.createHttpClient` disponível (supabase-edge-runtime 1.74.3 / Deno 2.1.4) → mTLS do Banco Inter é viável no runtime; falta Client ID/Secret + certificados. `GET ?capability=1` responde só a capability, sem segredo.
- Estado dos trilhos (11/08/2026): **nenhum PIX recorrente disponível**. Asaas restrita; Woovi em análise cadastral (72h); Banco Inter exige "Solicitar Integração" com prazo de **até 30 dias úteis**. Portanto: cartão Stripe é o único trilho de venda, e o health gate mantém o PIX escondido no checkout até algum trilho voltar. Não prometer PIX em copy/anúncio enquanto isso.

- **Sonda real do Inter (histórico, 11/08/2026, mTLS OK)**: com `INTER_CLIENT_ID`, `INTER_CLIENT_SECRET`, `INTER_CERT_PEM` (X.509 base64) e `INTER_KEY_PEM` (PKCS#8), o `inter-probe` obteve **token 200** via `Deno.createHttpClient` — mTLS funciona no Edge Runtime. Escopos concedidos: `cob.read cob.write pix.read pix.write` (Pix Cobrança). Escopos `pix.automatico.*` e `recorrencia.*` retornam **401 "No registered scope value for this client has been requested"**, e `GET /pix/v2/recorrencia` responde **404**. Conclusão: a integração/conta do Inter ainda **não tem Pix Automático habilitado** — é liberação comercial no Internet Banking (Integrações via API → adicionar escopo Pix Automático / solicitar habilitação), não problema técnico nosso.
- **Trilho Inter montado e validado ponta a ponta (11/08/2026)** — Jornada 3 do Bacen (QR composto: paga o 1º ciclo **e** autoriza o mandato no mesmo scan, mesma UX do "QR integrado" do Asaas). Sequência obrigatória: `POST /pix/v2/locrec` (loc do mandato, ID numérico) → `POST /pix/v2/loc` (`tipoCob: "cob"`) → `POST /pix/v2/cob/{txid}` (cobrança imediata do trial/1º ciclo) → `POST /pix/v2/rec` com `ativacao.dadosJornada.txid` = txid do `cob` e `loc` = id do `locrec`. Sem o `locrec` o Inter recusa com `RecOperacaoInvalida`. O `rec` nasce `CRIADA` / `tipoJornada: AGUARDANDO_DEFINICAO` e resolve para JORNADA_3 no scan.
- **`_shared/inter-pix.ts`**: mTLS (`Deno.createHttpClient` com `INTER_CERT_PEM`/`INTER_KEY_PEM`), OAuth com cache de token (o Inter tem rate limit agressivo → 429 sem cache), `interFetch`, `buildTxid` (26-35 chars) e `brtDate`. O Inter **não** devolve imagem de QR, só `pixCopiaECola` → `criar-pix-recorrente-inter` gera SVG via `qrcode` e responde `qrCodeImage` como **data URI** (o Asaas responde base64 puro; `CheckoutV2` trata os dois).
- **`criar-pix-recorrente-inter`**: paridade de contrato com `criar-pix-recorrente-asaas` (trial de 7 dias a R$ 6,90 só no mensal e só pra cliente novo, checagem de retornante cross-gateway, log em `checkout_sessions`, resposta `qrCodeImage`/`copyPaste`/`expiresAt`). Ciclos mapeados pros enums Bacen: `MENSAL`/`TRIMESTRAL`/`SEMESTRAL`/`ANUAL`. TTL do QR: 24h.
- **`webhook-inter`**: uma função para as três rotas do Inter (`PUT /pix/v2/webhookrec`, `/pix/v2/webhookcobr`, `/pix/v2/webhook/{chave}`, todas registradas apontando pra ela). `pix[]` = liquidação do QR composto → libera acesso; `recs[]` = ciclo do mandato (`REJEITADA`/`CANCELADA` → grava `payment_failed_at` e o dunning assume com o link de reautorização); `cobsr[]` = ciclos seguintes (`CONCLUIDA` → estende acesso; `CANCELADA` → dunning). Idempotência por `inter_webhook_events.event_key`; sempre responde 200 pra não gerar reentrega infinita.
- Tabelas: `inter_pix_recurrences` (mandato), `inter_pix_charges` (uma linha por ciclo, `cycle_index=0` é o trial), `inter_webhook_events` (dedupe).
- **Promoção do trilho**: `system_config.pix_gateway = "inter"` liga o Inter no `CheckoutV2` e no `asaas-health-check`. Enquanto ficar `asaas`, o PIX segue escondido pelo health gate (conta Asaas 401).
- Funções novas precisam de entrada em `supabase/config.toml` (`[functions.<nome>] verify_jwt = false`) — sem isso o deploy responde "not found in the codebase".
